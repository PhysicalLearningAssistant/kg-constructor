# 电磁学课程知识图谱文件格式规范 v1.0

| 项目 | 值 |
| --- | --- |
| 格式版本 | `1.0.0` |
| 日期 | 2026-10-16 |
| 规范对象 | 最终输出的知识图谱文件 `graph.json` |
| 配套定义 | `graph.schema.json`，JSON Schema Draft 2020-12 |

本文只约定知识图谱文件的数据结构、字段含义和一致性约束。知识图谱生成器是独立项目，其技术栈、抽取方式、模型、审核流程、数据库和部署方式均由该项目自行决定。本规范不定义生成器实现，也不定义 Agent Tool、MCP 或 HTTP API。

## 1. 文件格式

- 交换文件为一个 JSON 文件，建议命名为 `graph.json`。
- 编码为 UTF-8，无 BOM；不得包含注释、尾随逗号、重复对象键、`NaN`、`Infinity` 或无法用有限数值表示的浮点数。
- JSON 是完整图谱的权威格式，不依赖 Neo4j、CSV、其他数据库或服务才能解释。
- 数组顺序不代表知识关系；关系只由 `edges` 明确表达。章节的展示顺序使用 `order`。
- 本目录的 `example.graph.json` 是合成格式示例，标记为 `draft`，不代表已审核的真实课程图谱。

## 2. 通用字段规则

### 2.1 ID

图谱、课程、章节、节点、关系、来源、证据、题目的 ID 使用同一语法：

```text
长度：1–128 个 ASCII 字符
正则：^[a-z][a-z0-9]*(?:_[a-z0-9]+)*$
示例：gauss_law、electric_flux、ch_electrostatics
```

- ID 在各自集合中唯一，不使用显示名称或数组下标充当 ID。
- 同一图谱各数据版本中的节点 ID 保持相同语义；同一 ID 不得重新代表另一个知识点。
- `item_id` 对应外部题库的稳定 ID。
- 文中的 ID 类型表示满足以上语法的字符串。可选 `rag_ref` 中的外部 RAG ID 不适用此语法。

### 2.2 字符串、空值与时间

- 文本使用 Unicode NFC，首尾不得含空白。非空字段不得用空字符串表示未知。
- 仅明确标注允许的字段可以为 `null`。空数组和空对象分别使用 `[]`、`{}`。
- 时间使用 UTC RFC 3339，例如 `2026-10-16T08:00:00Z`；秒值为 00–59，不使用无时区时间或闰秒表示。
- LaTeX 按 JSON 字符串转义，例如源文件中 `"\\nabla"` 表示文本 `\nabla`。
- 未声明字段不允许出现；扩展信息只放在 `extensions` 中，键采用命名空间形式，如 `team.difficulty`。

### 2.3 版本

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `schema_version` | 文件格式版本 | 本版固定为 `1.0.0` |
| `version` | 图谱数据版本 | 三段非负整数，例如 `1.0.0`，不带前导零 |

同一 `(graph_id, version)` 对应一个确定的数据快照。格式版本与课程图谱的数据版本相互独立。

## 3. 顶层对象

以下字段全部必填；允许为空的数组和对象也必须保留。

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `schema_version` | string | 固定 `1.0.0` |
| `graph_id` | ID | 图谱系列 ID，例如 `electromagnetism_university` |
| `version` | string | 图谱数据版本，例如 `1.0.0` |
| `status` | enum | `draft` 或 `released` |
| `created_at` | UTC datetime | 此数据文件的导出时间 |
| `course` | object | 课程信息，见第 4 节 |
| `chapters` | array | 至少一条章节，见第 5 节 |
| `sources` | array | 至少一个来源，见第 6 节 |
| `evidence` | array | 至少一条证据，见第 7 节 |
| `nodes` | array | 至少一个知识节点，见第 8 节 |
| `edges` | array | 知识关系，可为空，见第 9 节 |
| `item_mappings` | array | 题目映射，可为空，见第 10 节 |
| `redirects` | object | 旧节点 ID 到现存节点 ID 的映射；无映射时 `{}` |
| `extensions` | object | 格式外的附加信息；无扩展时 `{}` |

`draft` 表示未定稿数据；`released` 表示最终定稿数据，具有第 11 节所述的更严格一致性要求。两者使用同一字段结构。

## 4. 课程 course

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `id` | ID | 是 | 课程 ID |
| `name` | string，1–200 字符 | 是 | 课程名称 |
| `language` | enum | 是 | `zh-CN` 或 `en` |

```json
{
  "id": "university_electromagnetism",
  "name": "大学电磁学",
  "language": "zh-CN"
}
```

## 5. 章节 chapters

每条章节具有以下全部字段：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | ID | 章节 ID |
| `title` | string，1–200 字符 | 章节标题 |
| `parent_id` | ID / null | 上级章节 ID；根章节为 `null` |
| `order` | integer ≥ 0 | 同级展示顺序；同一上级下必须唯一 |

`parent_id` 必须引用现存章节，章节层级不得自引用或成环。章节层级仅为元数据，不作为新的知识关系类型。

## 6. 来源 sources

每条来源具有以下全部字段：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | ID | 来源 ID |
| `title` | string，1–500 字符 | 教材、讲义或其他资料名称 |
| `edition` | string，1–200 字符 | 资料版本、出版年或修订号；未知时写 `未注明` |
| `source_type` | enum | `pdf`、`docx`、`markdown`、`web` |
| `uri` | string / null | HTTPS 地址或 `asset://` 资料标识，最长 2048 字符 |
| `sha256` | string / null | 原始文件字节的 SHA-256，64 位小写十六进制 |

- `pdf/docx/markdown` 的 `sha256` 必须非空；`web` 的 `uri` 必须为 HTTPS 地址。
- URI 必须含有效 authority，不含用户名、密码或访问密钥，不使用机器私有绝对路径或 `file://`。
- `asset://` 表示外部资料库的稳定标识；文件格式不约定资料库实现。

## 7. 证据 evidence

每条证据具有以下全部字段：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | ID | 证据 ID |
| `source_id` | ID | 引用 `sources.id` |
| `locator` | object | 来源定位，结构见下表 |
| `quote` | string，1–4000 字符 | 支持对应知识记录的原文片段，不是摘要 |
| `rag_ref` | object / null | 外部 RAG 关联；未关联时 `null` |

`locator` 的全部字段必填：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `section` | 非空 string / null | 小节编号或章节路径 |
| `page_start` | integer ≥ 1 / null | 起始页 |
| `page_end` | integer ≥ 1 / null | 结束页 |
| `anchor` | 非空 string / null | 标题锚点或资料内稳定定位标识 |

section、页码范围、anchor 至少存在一种有效定位。页码必须成对提供，且 `page_start ≤ page_end`；PDF 使用文件物理页码，从 1 开始。

`rag_ref` 非空时严格为以下结构，两个字段均为非空字符串：

```json
{
  "file_id": "file_external_id",
  "parent_id": "parent_external_id"
}
```

`rag_ref` 只是可选元数据，文件不能依赖 RAG 才能解释；原始资料版本及定位以 source、sha256、locator 为依据。

## 8. 知识节点 nodes

所有节点统一为逻辑实体 `Object`，用 `type` 分类。

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `id` | ID | 是 | 知识点 ID |
| `name` | string，1–200 字符 | 是 | 主名称 |
| `type` | enum | 是 | 六类之一，见下表 |
| `description` | string，1–8000 字符 | 是 | 定义或含义 |
| `chapter` | ID | 是 | 引用主归属章节的 `chapters.id` |
| `aliases` | string[] | 是 | 别名；无别名时 `[]`；单个别名 1–200 字符 |
| `formula_latex` | 非空 string / null | 是 | formula 节点必须非空，其他类型必须为 `null` |
| `conditions` | string[] | 是 | 元素非空；物理前提、适用条件；无附加条件时 `[]` |
| `evidence_ids` | ID[] | 是 | 至少一条现存证据，无重复 |
| `review` | object | 是 | 审核状态元数据，见第 11 节 |
| `extensions` | object | 是 | 无扩展时 `{}` |

`conditions` 的元素须为非空字符串，数组本身可以为空。

| type | 含义 | 示例 |
| --- | --- | --- |
| `concept` | 概念 | 电场强度、电通量、高斯面 |
| `law` | 定律或定理 | 高斯定理、安培环路定理 |
| `formula` | 公式 | 高斯定理积分形式 |
| `method` | 解题方法 | 高斯面法、叠加法 |
| `application` | 应用或典型问题 | 均匀带电球面的电场 |
| `phenomenon` | 现象 | 静电屏蔽 |

- `formula_latex` 不含 `$` 或 `$$` 外层定界符；公式采用的单位制、适用条件放入 `conditions`。
- `conditions` 表达物理条件，`prerequisite` 表达学习先修关系，二者语义不同。
- 同一节点的别名规范化后不得重复，也不得与规范化主名相同。规范化规则：NFC、去首尾空白、连续空白压为一个 ASCII 空格、ASCII A–Z 转小写。
- 不同节点可以共享名称或别名，文件以 ID 区分实体，名称不是唯一键。
- `conditions` 的重复元素不允许存在。

## 9. 知识关系 edges

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `id` | ID | 是 | 关系 ID |
| `source` | ID | 是 | 起点节点 ID |
| `target` | ID | 是 | 终点节点 ID |
| `relation` | enum | 是 | 三类之一，见下表 |
| `description` | string，1–2000 字符 | 是 | 关系含义或依据 |
| `evidence_ids` | ID[] | 是 | 至少一条现存证据，无重复 |
| `review` | object | 是 | 审核状态元数据 |
| `extensions` | object | 是 | 无扩展时 `{}` |

| relation | 语义 | 存储规则 |
| --- | --- | --- |
| `prerequisite` | A → B：A 是学习 B 的先修知识 | 有向，source=A，target=B；先修子图无环 |
| `derives` | A → B：A 推导出 B，或 B 是 A 的数学表达/应用结果 | 有向，source=A，target=B |
| `related_to` | A ↔ B：一般关联、类比、工具关联 | 无向，只存一条；按 ASCII ID 顺序保证 source < target |

关系一致性：

1. source 和 target 必须引用现存节点，且不得相同。
2. `(relation, source, target)` 不得重复；related_to 的反向记录也视为重复。
3. 同一对节点可以具有不同 relation，必须以不同关系记录表示。
4. prerequisite 记录直接先修关系，不得同时包含已被更长先修路径表达的冗余直接边。例如 A→B、B→C 已存在时，不再记录直接 A→C。
5. 无环要求只作用于 prerequisite 子图，不作用于 derives 或 related_to。

## 10. 题目映射 item_mappings

本字段是图谱文件中的可空附加集合，不要求每份图谱必须带题库数据。未收录题目映射时使用 `[]`。

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `item_id` | ID | 是 | 外部题库 ID，同版本唯一 |
| `skill_ids` | ID[] | 是 | 1–3 个现存节点 ID，不重复 |
| `confidence` | number / null | 是 | 范围 `[0,1]`；未提供自评值时 `null` |
| `evidence_ids` | ID[] | 是 | 至少一条现存题目/解答来源证据 |
| `review` | object | 是 | 审核状态元数据 |
| `extensions` | object | 是 | 无扩展时 `{}` |

`skill` 为题库映射用语，不是额外节点类型。confidence 为数据提供方的自评信息，不表示学生掌握度；未附校准说明时不能视为正确概率。

## 11. 审核状态元数据 review

本节仅定义文件内状态的含义及字段一致性，不规定如何审核。

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `status` | enum | 是 | `pending/approved/rejected` |
| `reviewer_id` | 非空 string / null | 是 | 审核者代号 |
| `reviewed_at` | UTC datetime / null | 是 | 审核时间 |
| `note` | 非空 string / null | 是 | 备注 |

- pending：reviewer_id、reviewed_at 必须为 null。
- approved/rejected：reviewer_id、reviewed_at 必须非空；rejected 的 note 必须非空。
- 审核时间不得晚于顶层 created_at。
- released 文件的所有节点、关系和题目映射必须为 approved，且无孤立节点。
- draft 文件可以包含上述三种状态，也可以有孤立节点；其他结构与引用约束仍生效。
- 状态字段本身无法证明人工审核真实性。

## 12. 旧节点映射 redirects

```json
{
  "gauss_theorem_old": "gauss_law"
}
```

key 为旧节点 ID，value 为当前节点 ID。必须满足：

- 旧 ID 不在 nodes 中，目标 ID 必须在 nodes 中。
- 不允许重定向链、自引用或循环。
- edges、item_mappings 必须直接引用现存节点，不能引用 redirects 的旧 ID。

## 13. 文件一致性检查

合法文件必须同时满足：

1. 严格 JSON 语法和 graph.schema.json 的字段约束。
2. 各集合 ID 唯一，所有章节、来源、证据、节点引用有效。
3. 章节层级无环，同级 order 唯一。
4. 证据定位有效，页码成对且范围有效，来源哈希和 URI 格式正确。
5. 节点分类、公式字段、别名及空值符合定义。
6. 关系无自环、无重复，related_to 存储顺序规范，prerequisite 无环且无冗余传递边。
7. 题目映射及 redirects 符合引用规则。
8. status=released 时满足第 11 节的定稿数据约束。

知识点数量、关系数量、课程覆盖率、抽取准确率不是文件格式约束。格式正确也不等于知识内容正确。

可选校验工具使用方式（Python 3.11+，依赖 `jsonschema>=4.18,<5`）：

```bash
python validate_graph.py graph.json

# 仅接受最终定稿状态
python validate_graph.py graph.json --release
```

校验器只检查文件格式和内部一致性，不要求使用特定生成器，不调用 RAG、模型或数据库。来源文件哈希、原文真实性、关系事实及审核真实性不由格式校验证明。

## 14. 与白皮书简略字段的对应

| 白皮书字段 | 本文件格式 |
| --- | --- |
| version="1.0" | 三段数据版本 version，以及独立 schema_version |
| chapter="静电场" | chapter 为章节 ID，标题在 chapters 中 |
| 节点 source="ch3.2" | evidence_ids → evidence → sources，保留章节/页码/锚点 |
| 简略边 source/target/relation | 增加关系 ID、描述、证据和状态元数据 |
| 公式作为普通名称或描述 | formula_latex 保存 LaTeX，conditions 保存适用条件 |
| related_to 双向 | 一条规范化存储的无向边 |

最终文件以本规范和配套 Schema 为准。完整可解析字段示例见同目录 `example.graph.json`。
